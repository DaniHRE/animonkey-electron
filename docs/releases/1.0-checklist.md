## Decisões de produto pendentes

- **Assinatura Windows:** decisão tomada pelo usuário para a 1.0: distribuir sem assinatura, pois não há identidade de publicador verificada nem certificado configurado. Authenticode não é requisito técnico do updater Squirrel no Windows, mas a ausência pode gerar avisos de SmartScreen/reputação; certas políticas do Windows podem impedir a abertura de binários sem reputação. Não inventar identidade de publicador.
- **Canal estável:** `main` é a fonte estável; Windows x64 será distribuído por GitHub Releases. Push em `main` só gera CI/artifact; uma release estável publicada com tag SemVer alcançável por `main` é o que disponibiliza versão ao updater. Outros sistemas/canais seguem fora da 1.0 inicial.
- **Auto-update:** implementado pelo `autoUpdater` do Electron com `update.electronjs.org`, que consome releases estáveis públicas SemVer. A verificação ocorre apenas em Windows x64 empacotado; aplicação baixa em segundo plano e solicita reinício. O teste de ponta a ponta da instalação do usuário 1.0.0 para 1.0.1 segue pendente até a publicação dos assets; rollback não será validado neste cenário.
- **Pipeline:** workflow `.github/workflows/release-windows.yml`: push em `main` ou `release/**` valida e compila; publicação de release estável validada anexa Setup, `RELEASES` e pacote completo. Os runs [44857046242](https://github.com/DaniHRE/animonkey-electron/actions/runs/44857046242), [44858239651](https://github.com/DaniHRE/animonkey-electron/actions/runs/44858239651) e [44859562985](https://github.com/DaniHRE/animonkey-electron/actions/runs/44859562985) passaram na branch release; o último inclui a URL imutável do ícone. - **Monitoramento externo:** sem serviço externo para a 1.0 inicial; revisão manual periódica de providers/contratos. Reavaliar serviço de alertas após haver operação e volume que justifiquem esse custo.
- **CSP de embeds:** decisão para a 1.0: manter `frame-src https:` para acomodar os hosts dinâmicos de providers. O player valida URL HTTPS e o renderer não tem Node nem IPC genérico. O risco residual fica documentado; reavaliar quando houver uma lista de hosts confiável e estável.
