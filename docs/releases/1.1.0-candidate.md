# Animonkey v1.1.0 Release Candidate

## Status

Version 1.1.0 is the proposed next stable release after v1.0.3. The minor increment is appropriate for the backwards-compatible discovery, library, privacy, notifications, playback, and diagnostics features accumulated on `dev`. Distribution remains Windows x64 through the existing unsigned Squirrel.Windows workflow.

This is a local release candidate on `release/1.1.0`, based on local `dev` at `c3734e9`. Local `dev` is 48 commits ahead of `origin/dev`, so remote CI cannot build these changes until the branch is synchronized. Windows x64 Squirrel artifacts were built in an isolated worktree and passed the package verifier. The extracted executable launched once with an isolated temporary profile; the Home page rendered and the production F12 shortcut remained disabled. The app was not installed. The candidate has not been merged to `dev` or `main`, pushed, tagged, or published.

The owner reports end-to-end development checks for playback with captions, search, pagination, and the update center showing the expected development version. These user-reported checks were not independently reproduced in the packaged executable.

## Candidate scope

- Screenshot-based anime lookup, header search preview, reliable pagination, scroll preservation, and safe-for-work discovery defaults.
- Local follows for airing anime, a local notification center, and an optional maintainer-controlled static notification feed.
- Watch-history privacy controls, title-language and caption-size preferences, configurable shortcuts, and sidebar route ordering.
- Finale continuation recommendations and Anivexa diagnostics, including the opt-in provider lookup failure report.
- Feedback intake for suggestions and bug reports, plus fixes to search, catalog, runtime diagnostics, and production DevTools behavior.

The user-approved `desktop-notifications` bucket is public-read, JSON-only, and limited to 4 KiB per object. Its only object is the empty `v1/feed.json`; a public GET returned HTTP 200 with `application/json` and `Cache-Control: public, max-age=3600`. It contains no user reports or operational health data, and no remote messages are published.

The connected Supabase project audit, feature map, deployment procedure, and migration-history limitation are documented in [Supabase deployment and project status](../supabase-deployment.md).

## Known limitations and operational checks

- Remote notifications are best effort and polled no more often than every six hours with jitter. No remote messages are published in the initial feed.
- Review current Supabase cached and uncached egress headroom before distribution. The feed adds no Edge Function invocations or application-table reads; its incremental estimate at 20 active client profiles is at most 2,500 reads and about 10.24 MB per 31-day month.
- DISC-29 provider probes and account-backed features depend on the configured Supabase project and their existing operational setup.
- The extracted smoke review verified startup and the production DevTools shortcut only. The update center could not check for updates during that run; this package smoke did not establish installation or stable-channel updating.
- The owner has since reported successful development-app checks for playback with captions, search, pagination, and the expected development version in the update center. Installation and stable-channel updating of the packaged 1.1.0 release remain unverified.

## Promotion path

After release-candidate validation, integrate the version bump and release notes into `dev`, then prepare the `dev`-to-`main` promotion for owner review. Do not merge to `main`, push, create `v1.1.0`, dispatch the release workflow, or publish a draft/public release until the owner separately authorizes those actions. The stable workflow expects the exact `v1.1.0` tag on `main` and creates a GitHub draft with the three Windows Squirrel assets.
